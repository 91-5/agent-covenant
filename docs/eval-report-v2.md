## 5. 为什么主端点没有差异：预注册自身的两处矛盾

这是本轮最重要的发现，且**不是事后辩解**——依据全部指向预注册原文：

1. **M1 的分子只有 E3**（v1.1 §2：`M1 = E3 / (E2+E3+E4)`）。而本轮全部失败都落在 **E2**（不可复现），E3 为 0 → 两臂 M1 都是 0%。
2. **M2 的分子只有 E0+E1**（`M2 = (E0+E1) / 全部断言`）。v1.1 的 C1 让两臂都必须带证据行，E0/E1 因此恒为 0 → 两臂 M2 都是 0%。
3. **而同一份预注册的 E 级表（§1 表，L30）明确把 E2 归入「无依据主张」列**——与 M2 的公式互斥；同理 §1 散文把「不可复现」列为假验证的一种形态，与 M1 的公式互斥。

⇒ 冻结公式与冻结表格**互相矛盾**，本轮按公式报告（保守），矛盾本身作为 v1.2 的 C5 修复项。

## 6. 本轮的预注册后变更（C4）

**代码层（T11–T20）本轮排除。** 执行者是 API 模型，**物理上无工具**，无法创建 `fib.py` 等实现文件；若纳入，两臂的验收命令都会因「文件不存在」失败，那是环境同源噪声而非认知误差，会污染 M1。按预注册 §0 记录为变更 C4，并在 v1.2 §8 存档。

因此本轮样本为 **20 任务**（事实 10 + 流程 10），低于预注册的 30 任务下限——**效应估计只能作初步信号**。

## 7. 失败样本附录（全量保留）

- 任务级失败：无（20 任务 × 2 臂 × 3 重复全部产出）

## 8. 局限性（五条原文 + 本轮追加）

1. 样本小：30 任务 × 2 条件 × 3 重复远低于能精确估计小效应的样本量，置信区间宽，未达最小效应不等于无差异。
2. 任务构造：任务由团队自建并自标注标准答案，构造偏差可能同时影响两个条件，配对设计只能缓解、不能消除。
3. 代理指标：E0-E4 判定测的是过程诚信（断言-证据链完整性），不是知识正确性；harness 不验证断言内容为真。
4. 单 adjudicator：盲化判定由唯一评审员承担，其系统偏好无法在本设计内交叉验证。
5. 同执行者：两个条件由同一执行者完成，执行者对假设的预期可能泄漏到产出中，只能靠盲化与负对照部分约束。

**本轮追加：**

6. **样本降至 20 任务**（代码层排除，见 §6），低于预注册下限。
7. **执行者无工具**：Spark 无法执行命令、无法读写文件——这是 B 臂「零执行」的结构保证，但也意味着它无法像真实 agent 那样「先试再报」，其错误模式未必代表带工具 agent。
8. **仪器出现未归因的不一致**（§4），本轮数字的可信度因此打折。
