## 2. 对抗性四问（独立挑战，坐实无阻断形态）

### Q-adv-1 runlog 是否被 A 臂「伪造执行痕迹」钻空子？——**未抬成判定锚**

runlog.py 只产出**记录**（`record`/`execute`/`RunLog`），全文 docstring 明确「记录返回数据、判定留 judge.py」，
**没有任何 runlog 字段被判定器消费**。E 级判定仍按既有 §1.3 冻结表 + judge.py 独立判。
协议 §13.2 把 run-log 措辞为「审计上下文，不是 §1.1 证据语法」，A/B 佐证（B 臂零记录）是**佐证形态**
（与第三轮 run-log-r3.json B 0 / A 126 先例同形态），非判定依据。verdict A2「判定器零改动」口径在本卡续用。
→ **判定器未因 runlog 被扩大/改变，无「软判定锚」形态。**

### Q-adv-2 `records_for(condition)` 跨臂混查？——**只按 condition 字段过滤，不跨臂合并**

源码 `records_for` 一行：`[r for r in self.records if r.get("condition") == condition]`——**纯等值过滤**，
既不 sum 计数、也不合并多臂。B 臂零记录由调用方对 `records_for("B")` 的长度断言读取（§3.3 先例），
不产生任何跨臂合并。本方独立驱动 `records_for("A")==1 / records_for("B")==0` 坐实。
→ **无跨臂混查。**

### Q-adv-3 C6「==30」是否写死到不可演进？——**预注册锚，非硬编码常量**

`tasks.py` 不写死 `30`，而是 `from schema import TOTAL_TASKS, LAYER_COUNTS`，`census_errors` 比较
`total != TOTAL_TASKS`。`schema.TOTAL_TASKS=30` 是**冻结设计常数**（注释「frozen: 10/10/10」），
与 `LAYER_COUNTS` 同源、是 C6 预注册口径的机读锚。预注册升版（若第四轮后扩样本）改 `schema` 一处即可，
`run.py --tasks` 的断言行随 `TOTAL_TASKS` 自动演进，**不会静默漂移**；漂移即 `census_errors` 报
「{total} != 30」→ exit 1 报警。→ **是预注册口径锚，非写死常量。**

### Q-adv-4 runlog.py 是否对判定器/密封仪器隐式依赖（软触碰）？——**纯 stdlib，零红区依赖**

runlog.py import 面仅：`json / subprocess / datetime / pathlib / typing / __future__`，**全部 stdlib**，
未 import 任何红区文件（judge/extract/stats/blind/seal_run/study_runner/m3_probe/gate/lint_cards）。
唯一跨文件符号是 `run.py --exec` 的 `judge.command_refused`（拒绝清单）与 `judge.DEFAULT_TIMEOUT_SECONDS`，
二者**基线 2b39767 的 run.py 已存在**（本方 `git show 2b39767:tools/eval/run.py` 证实），本卡新增的
`cmd_exec` 只复用既有 judge 接口、未改动 judge.py 本体。runlog.py 本身对判定器/密封仪器**零依赖**。
→ **无软触碰红区。**
