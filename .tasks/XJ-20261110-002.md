## 陷阱与决策记录（接手者照做，别重踩）

1. **净下降不是失败**：报告必须给「+48 / −102」分解与「偶然一致」机制说明；**只报下降后的数字**或**只报 §16 命中率**都是选择性报告，评审会打回。
2. **回放的工作区必须在仓库内**：`replay_r1.py` 默认把 C10 工作区重建到 `<repo>/.eval-sealed/` 下。若改到仓外临时目录，6 条 git 类条目的判定会翻转（仓内 git 可见、仓外不可见），覆盖率读数由 57 变 63——那是**保真度 bug，不是发现**。
3. **分臂主轨断言面要按记录覆盖的码过滤**：A 臂 = 90 码 × 5 = **450** 条主轨断言（不是 900）。不过滤会让 `alignment_rate` 变成 0.5（错）。
4. **轮九 run-dir 必须沿用执行者产物原样**：若用 `study_runner` 重新生成产物，runner 的复跑段落会被今天的观察值改写 → 主轨判级漂移 **84/900**（该变体已留档为 anomaly）。沿用原样产物后漂移仅 **3/900**。
5. **3 条漂移的成因**：cmd.exe 报错语种由中文变英文（`ForEach-Object` 三条 `P0xx-c05`）——环境不可控，如实披露即可。
6. **产物里有两套证据行**：执行者自报段（believed 值）+ runner 复跑段（真实观察值）；`extract.py` 两段都抽。理解这一点才不会误判「证据行不一致」。
7. **D-00 的两处缺陷**（登记为待查项，**不就地改写 D-00 文件**）：① I2 族 `reason` 字段是族级样板文字（称「判 E4」），与同条 `main_level` 字段矛盾；② `docs/d00-mismatch-analysis.md` §4.2 表把 15 条轮六条目的主轨判级写成 E4，密封判定实为 **E3**（该表截断了判级 detail，而「命令已复现…」是 E3/E4 共有的 `reproduce()` 前缀）。

9. **冻结序执行史要披露**：首次探索性回放曾先于真数据运行；最终交付链已按 freeze → replay → data 顺序重跑（§16 commit `123279b` 12:47:05 < `out/replay_r1.json` 13:07:58 < `run-dir-r9` ~13:26 < `shadow-r9/alignment-split.json` ~13:30）。§16 文本自冻结后**零改动**，D1 仪器改动亦早于首次真数据。
