**My addendum's clean-checkout figure was wrong, and the reviewer repeated it.** I claimed "a
clean checkout of `9928bec` yields 17 blocking / 31 advisories". The run was

verdict card as the clean-checkout result. **The false figure travelled from my evidence into
another agent's evidence because neither of us checked the CWD.** Every other false claim in
this repository's history (rounds 5, 7, 8, 9) was caught by a checker; this one passed
through two pairs of eyes because it looked like a measurement.

post-verdict state as "6 blocking / 42 advisories", which assumed this round's verdict would
be PASS. It was FAIL, so the chain carries a fifth `VERDICT_FAIL` and checks 10 ids. The
reviewer measured 7 / 10 / 42 and corrected it. A projection about a verdict that has not
landed is not a measurement.

This is the fifth false claim in the record, and the first one I authored inside evidence
aimed at proving I was not overclaiming.

## A rejected option, recorded so it is not re-proposed

The 012 review suggested clearing the residual `templates/TASK.md` staleness with "a
maintenance id that re-maps `templates/TASK.md`". **Rejected.** A round that maps a file it
never changed would attest freshness it did not earn, and once such a round exists, "re-map it
next cycle" retires any staleness on demand — the laundering channel the `SUPERSEDED` rule
exists to close, opened from the other side. The real defect is that `artifacts.json` carries
two incompatible duties: **claim-surface coverage** (a round must not omit a README or
`UNMAPPED_CLAIM_SURFACE` fires) and **round-scope declaration** (a round should list what it
edited). 012 had to list both READMEs it never touched, because the first duty demanded them.
Splitting the duties is the honest fix; it requires changing `gate.py`, so it belongs to a
future round, and this card records the conflict rather than quietly picking a side.
