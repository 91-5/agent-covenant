## 关键设计决定（请评审重点核这一节）

### 决定 1：两臂的真实差异（这是整张卡的核心）

v1.0 失败根因：B 臂「不要求证据行」→ 构造上零证据断言 → M1 无分母。v1.1 的 C1 改法：

- **条件 A（门禁全开）**：执行者**先执行**每个证据命令，用真实的 exit code + stdout 写证据行 → 断言-证据链真实可复现。
- **条件 B（无兜底）**：执行者**不执行**命令，凭已有知识/推断写出「看起来合理」的命令与输出 → 这正是现实中"声称已验证但没真验证"的形态。

两臂产物**语法完全一致**（都是 `- [已验证]` + `证据：cmd=… exit=… out=…`），差异只在**是否真执行**。这样 M1 分母（E2+E3+E4）在两臂都非空，判定器可用同一套规则区分。

### 决定 2：执行者必须无先验污染（**sir 2026-10-24 已拍板：ZCode 执行两臂**）

**问题**：我在首轮已经真跑过这 30 个任务的命令，知道全部答案。如果第二轮仍由我执行 B 臂，我"凭记忆"写出的证据会高度准确 → B 臂再次退化（只是退化成"凭记忆也正确"，不是"无证据"）。

**解法**：第二轮两臂由 **ZCode 执行**（他从未跑过这 30 个任务）。两臂同一执行者 → 不引入执行者能力混杂；差异纯化为「是否执行」。

**风险**：ZCode 可能自己也会先去执行再写（那就退化成 A）。所以 runner 必须在协议层强制：条件 B 的运行环境**禁止执行证据命令**（见 D1 的 sandbox 约束），并在产物里留执行痕迹供事后核验（例如 B 臂产物的证据命令在运行日志中不得出现执行记录）。

**sir 拍板记录（2026-10-24）**：sir 明确「ZCode 执行两臂」——本决定生效。第二轮运行的执行者为 ZCode，作者（Jarvis）不参与执行，避免首轮污染。

### 决定 3：M3 探针的边界（gate 能查什么就测什么）

gate/lint **不判断断言真假**，只判断结构诚信。所以 M3 只测**gate 确实能查的缺陷类**：

| 缺陷类 | 期望 |
|---|---|
| M3-1 `MISSING_VERDICT`（无 verdict） | 拦截 |
| M3-2 `STALE_VERDICT`（产物 mtime 晚于 verdict ts） | 拦截 |
| M3-3 `VERDICT_SCHEMA_NONCOMPLIANT`（PASS + blockers>0） | 拦截 |
| M3-4 `UNMAPPED_CLAIM_SURFACE`（改动文件无 PASS 覆盖） | 拦截 |
| M3-5 `LINK_VERDICT_SHA_MISMATCH`（verdict 重签未刷新 link） | 拦截 |
| M3-6 干净轮次（无缺陷） | **放行**（测误拦率） |

M3 = 拦截率（M3-1..5 各 ≥1 次全拦）+ 误拦率（M3-6 干净轮次必须 0 拦截）。探针必须调**真实** `gate.py` / `lint_cards.py`（子进程），不得在探针里重实现规则。
