## Context

`PROTOCOL.md` §6.2 P1 写着：

> Require the id in the pre-push check.

**这是一句文档，不是一道机器。** 全仓 `.git/hooks/` 只有 git 自带的 `pre-push.sample`（未启用）。本仓已经为「无机器拦截」付过两次账：

2. **四个提交在 P1 生效期间上了远端**（`e7befe0`/`93d1376`/`cd04aa2`/`b754ae4`）——手册原话：「谁推的、为何能推得进去未作断言，但已发生是事实」。

CI（`gate.yml`）已存在，但它是**事后门禁**：push 已发生，红了只是通知。pre-push hook 的价值在**事前**——本地 `git push` 直接失败，未评审的变更出不了机器。两者互补。

**设计输入（Archify 图分析的落点 #1，sir 2026-10-13 拍板「最值得先做」）**：那张图的「三入口共用一个证据门」直接对应本仓缺口——写入路径不统一，绕卡的提交能漏进远端。

### CI 已解决的先例问题：全量红

全目录 gate（不带 `--require`）在当前仓库会因**历史 STALE 债**永久红。`gate.yml` 的解法（注释明说了理由）：

> Gating every historical verdict would be a permanently red build. … What CI
> must assert is that the round being shipped is signed and current.

即**只要求 artifacts.json 里的最新一轮 id**。hook 采用同一口径——与 CI 同判官、同范围，零漂移。

## Deliverables

### D1 —— `tools/pre-push-hook.sh`（hook 本体，可执行）

`git push` 的 pre-push 钩子。git 传给它 stdin：`<local ref> <local sha> <remote ref> <remote sha>` 每行一条。

逻辑：

1. **只拦非删除、非 tag 的推送**（ref 行含 `:0000000000000000000000000000000000000000` 删除目标、或 ref 以 `refs/tags/` 开头 → 跳过）。
2. 解析出待推分支名（`refs/heads/<name>` → `<name>`）。
3. 跑与 CI **完全相同**的命令序列，任何一步非零 → 拦截：
   - `python tools/lint_cards.py --dir .tasks --verdict-dir verdicts --artifact-map artifacts.json --strict`
   - 解析最新轮 id：`python -c "import json;m=json.load(open('artifacts.json'));print([k for k in m if not k.startswith('_')][-1])"`
   - `python tools/gate.py --verdict-dir verdicts --artifact-map artifacts.json --require <最新轮id>`
4. **`REPO_ROOT` 自定位**：脚本用 `$(cd "$(dirname "$0")/.." && pwd)` 推出仓库根——hook 被 git 调用时 CWD 是仓库根，但**不能依赖**这个（`core.hooksPath`、worktree 场景会变）。
5. **Python 解释器探测**：`command -v python3 || command -v python`，找不到 → 拦截并提示（fail-closed，不静默放行）。
6. 拦截时 stderr 输出**人类可读的原因 + 跳过方式**（`git push --no-verify`），且**明说跳过会被记录在你的 shell 历史里**——威慑而非纯技术封堵。
7. 空推送（stdin 为空，如 `git push --dry-run` 某些形态）→ 放行。

### D2 —— `tools/install-hooks.sh`（安装器，可执行）

`.git/hooks/` **不进版本控制**——每个克隆要自装。安装器做三件事：

1. 把 `pre-push-hook.sh` 复制/链接到 `.git/hooks/pre-push`（已存在且内容不同 → 备份为 `pre-push.bak.<timestamp>`，**绝不覆盖不询问**）；
2. `chmod +x`；
3. 处理 `core.hooksPath`：若 git 配置了自定义 hooks 目录，装到那里并**打印警告**（自定义目录可能被别的工具管理）。

幂等：重复运行无副作用。
