## Review questions

**Q1 — Does the new §8 text actually match the tool? Any third place still
implying "archived ⇒ delete verdict"?**

Consistent. `check_verdict_pairs` (`tools/lint_cards.py:267-278`) flags
`ORPHAN_VERDICT` for `verdict_ids - card_ids` and `VERDICT_WITHOUT_REVIEW` for
`card_ids - verdict_ids`. The `card_ids` handed to it at line 773 is
`card_ids | _legacy_card_ids(card_dir)`, and `_legacy_card_ids` (line 592-607)
scrapes any namespaced id out of `<card-dir>/legacy/*.md`. So a verdict survives
in `verdicts/` for an archived card and is never reported orphan. That is exactly
what §8 now says: "An archived card's verdict therefore stays in `verdicts/` and
remains paired with its id … such a verdict is **not** an `ORPHAN_VERDICT`."
Regression `test_verdict_for_archived_card_is_not_orphan`
(`tests/test_lint_cards.py:532-540`) asserts the same. Text and tool now agree.

I swept the tree for a third teaching of the old rule. The only surviving copy of
the deleted sentence is in `.tasks/legacy/XJ-20261003-002.md:210`, where it is
quoted as the reason that archive deviated — i.e. it is preserved **as history**,
not as guidance. `CHANGELOG.md` mentions it only to describe the fix. `README.md`,
`README.zh-CN.md`, `ADR-0001.md`, `CONTRIBUTING.md`, and the workflow file were
grepped for `verdict` / `archive` / `legacy` / `orphan`; none teach deletion.
**No third active location found.** Non-blocking.

**Q2 — Is the `ORPHAN_VERDICT` Fix rewrite over-narrowed? Can a true orphan still
be fixed?**

No, and yes. The new Fix column reads: *"Restore the card (active or under
`legacy/`), or delete the verdict of a card that never existed."* The deleted
Fix text ("Delete the verdict or restore the card") was **over-broad**, not the
new one over-narrow: it told the reader to delete verdicts that the tool in fact
keeps paired. The new text keeps both executable paths for a *true* orphan (an id
in neither the active dir nor `legacy/`): restore a card, or — for a verdict whose
card genuinely never existed — delete it. The tool's WARN still fires for exactly
that case (`verdict_ids - card_ids`), so the signal is unimpaired. Semantics of
`ORPHAN_VERDICT` are unchanged; only its boundary was corrected. **Not
over-narrowed.**
