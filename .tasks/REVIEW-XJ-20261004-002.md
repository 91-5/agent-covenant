## Review questions

### Q1（最关键）：修 B1 该走 (b) 还是该新写 ADR-0002？

**判作者方向正确，维持 (b)。** 理由：

- 本仓立身之处就是「不许 spec 比工具说得多，缺的要说缺」（P4/P5、ADR-0001 Alternatives 表第 2 行对「silently delete」之戒）。(b) 是这个精神在引用层面的应用：错引用的修复方式是**承认依据不存在**，而不是制造一个依据。
- 现编 `ADR-0002` 会犯 ADR-0001 自己拒绝过的同一种罪的镜像：给一个尚未发生、证据不足的 card-schema 迁移决策（迁移所有既有卡 + 新字段语义 + gate 升级时机）落纸面。那等于把「查不到」变成「查到了，但查到的没经过评审」，比原来的错引用更糟——原来至少还指向一份真实存在、内容正确的 ADR。
- 「recurring 的 schema 问题值得现在就落 ADR」的反方论证不成立，因为**它并不 recurring**：追溯卡机制（§6.2 P2）引入未满 48 小时，`retrospective: true` 从未被任何卡实际使用；唯一的复现来源是两处文本共用同一处错引用，一处修两处即消。真正的触发条件（某张卡真的声明 `retrospective: true`、或该升级 error）出现时，才有真实证据支撑 ADR-0002。
- 因此本卡 PASS 的方向成立；但应配一条跟踪机制（见 Non-blocking 第 1 条），使「暂无 ADR」这个状态不会静默变成「永远没人想起」。

### Q2：「No ADR covers that yet」是否记账正确？

是**方向正确的否定式记账**——比一句「(pending)」占位更彻底：说清了缺的是哪份 ADR、为什么需要它（迁移代价）。但「yet」之后没有挂钩子，读者确实会以为项目欠着债且无人理会。建议（非阻塞）：在 `ADR-0001.md` 的 Revisit-trigger 第 3 条（card schema 因故要变时）里显式点名「含 `retrospective` 字段的追溯卡 schema」，使这条缺口的 revisit 路径落在一份已有且被引用的文件里。这是一句 docs-only 的顺手活，可随 verdict 落地后的同一提交做掉，或单独开一张小卡；**不构成退回理由**。

### Q3：§6.1 第 255 行的 `see ADR-0001` 是否漏网之鱼？

**不是。** 该处讲「v0.1 has no machine-checkable acceptance ids to cross-reference (see ADR-0001: the card schema would have to change first)」——ADR-0001 的 Decision 段与 Consequences 段（「Introducing acceptance ids later is a schema migration for existing cards」）精确覆盖此内容。作者未动它是对的。

### Q4：`XJ-20261003-001` 的 verdict 怎么收尾？给一个可复用的规矩

**可复用规矩（建议记入 PROTOCOL.md §6.1 supersession 段或其下新增小节，随本 verdict 落地后由作者落笔）：**

> **fix-card-records-resolution 规则：** 当一个 CONDITIONAL verdict 的 condition 由后续**修复卡**修掉时，**不重发原卡 id 的 verdict**（两份同 id verdict 会让 §6.1 无法区分新旧两份权威），也**不在原 verdict 上追加**（历史 verdict 文件应不可变）。由**修复卡自己的 verdict** 携带一个 `unblocks: "<原卡id>.<conditionid>"` 字段，并在其 review 文档中独立验证原条件已消解。原 verdict 作为历史保留，不改一字；其条件在 `unblocks` 处被引用、被关闭。两份 verdict 都留在 `verdicts/`，同目录即链，§6.1「reported, never dropped」不变。

对本卡的具体操作：本 verdict（`XJ-20261004-002`）带 `unblocks: "XJ-20261003-001.C1"`；`XJ-20261003-001` 的 CONDITIONAL verdict 原样保留。同一规矩适用于 `XJ-20261004-003`（它卡住 `XJ-20261003-002` 的 C1）：那张的 verdict 应带 `unblocks: "XJ-20261003-002.C1"`。**注意：** `unblocks` 目前不在 `gate.py` 的 REQUIRED_FIELDS 里，属**建议性扩展字段**，不写不破坏机检；若采纳，建议后续在 `tools/lint_cards.py` 的 verdict-schema 校验里把它列为「已知扩展字段」，避免将来误报。
