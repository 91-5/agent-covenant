## Answers to the review questions

**Q1 —— `SELF_SIGNED_CONTRADICTION` 的「矛盾即报错」会不会太激进？**

**不激进，定位正确。** 关键是它检测的是**内部矛盾**，不是「自签」本身：

- 「作者自签但确实做了诚实复核」的情形，**正确写法**是 `self_signed:true,
  independent:false`——这是**如实记账**（`XJ-20261003-001` 该是但写错成
  `independent:true`）。这条走 `NOT_INDEPENDENT`（A3a 我复现过），且
  `--allow-nonindependent` 可放行，**不惩罚**。
- `SELF_SIGNED_CONTRADICTION` **只在「同时填 `self_signed:true` 和
  `independent:true`」时触发**——这是**两个字段互相矛盾**的 schema 完整性错误，
  等价于本仓「一个 id 不得有两份权威」的原则在字段层的镜像：你不能一边说「这是自签」
  一边说「这是独立」。它抓的是**自相矛盾/数据完整性**，不是「自签」的判罚。
- 所以它精确落在 R3「what it removes is the *authority*, not the *admissibility*」
  上：矛盾者（声称自签又称独立）**失去权威资格**；诚实自签者（`independent:false`）
  **不失去可被 `--allow-nonindependent` 接受**。判定：**保持原样，不对。**

**Q2 —— `unblocks` 只验格式、不验被引条件是否存在，这个理由成不成立？**

**理由成立，且是**正确**的边界切分；但存在一个可行的后续增强，我给出方向，
不列为本卡 blocker（它本就是 ADR Revisit-trigger item 2 明确延后的缺口）。**

- 作者理由对：本仓 condition id 是**自由文本前缀**（`-001`/`-002` 的 `C1: …`、
  `-004` 的 `C1 (B1, from Q2): …`），要验「被引条件存在」就得解析散文。本卡只做
  格式 + 自引用是**诚实地把越界部分切出去了**。
- **可行的验证方式（供 revisit-trigger item 2 后续卡实现，非本卡）**：对 `unblocks`
  值 `"<orig>.<cond>"`，(a) 载入被引卡 `verdicts/<orig>.verdict.json` 的
  `conditions` 数组；(b) 对每条 condition 取 `^\s*([A-Za-z]\d+)` 前缀（`"C1 (B1,
  from Q2)"` → 规范化为 `C1`，即**去括号取前缀**）；(c) 断言 `"<cond>"` 的
  前缀 ∈ 该集合。这条能堵住「引用一个不存在的条件 id」而无人发现。它是
  **跨卡加载 + 前缀规范化**两步，属于可机检增强，但**确实超出了本卡「格式校验」的
  承诺范围**。我判定：**本卡保持 (b)（不验存在性）是对的**；(a) 列为 revisit-trigger
  item 2 的推荐解法。
- **是否 blocker？否。** ADR 自己把「unblocks 声称是假的」写进 Revisit-trigger item 2，
  这是**已记账的已知缺口**，不是遗漏。本卡按「已定范围」实现得完整。

**Q3 —— R4 正例「`unblocks` 不洗白 STALE」的构造方式可靠吗？**

**可靠，且构造得当。** `test_unblocks_does_not_launder_a_stale_finding` 在**临时目录**
构造：artifact 先写、`os.utime` 推到未来使其 mtime 晚于 verdict ts、且 artifact 无
later verdict → 断言 `STALE` 仍被报、`SUPERSEDED` 不出现。**不污染 `verdicts/`**，
比临时目录更可靠的方案不存在（真要污染 `verdicts/` 才更糟）。反向证明
`test_unblocks_never_produces_superseded` 更强（002 的 artifact 列表为空，
「无论如何 unblocks 都产不出 SUPERSEDED」）。
**一个我认可作者自陈的次要点**（非 blocker）：`test_self_signed_cannot_supersede_
another_finding` 证明了「行为正确」（无 SUPERSEDED），但**没构造出「若无
`allow_nonindependent=False` 这行改动，则会被误判 SUPERSEDED」的对照**——即证明了
行为、未证明该改动是**必要的**。这是**测试强度**缺口，不影响正确性。建议（非
blocker）：后续补一条对照，或在该测试 docstring 里显式记录「必要性由
`_successor_candidates` 的 `allow_nonindependent=False` 强制，本用例只锁行为」。

**Q4 —— 该不该把 `retrospective: true` 一起做了？**

**不该，作者的直觉正确。** `retrospective` 是**另一个 schema 字段 + 另一条 gate
规则 + 另开 ADR-0003**（`§6.2` 末段那句「等自己的 ADR」至今悬着，且 `§6.2` 明确
「a card-schema change would migrate every existing card」需要独立 ADR 背书）。
本卡 scope 是「落实 ADR-0002 的 R1~R4」；把 `retrospective` 塞进来会**污染卡边界**
（一张卡验两个未定的 schema 变更，违反本仓「一卡一决」精神）且会把 §6.2 那个
「需要自己 ADR 背书」的字段提前实现——**它现在没有 ADR，本卡无权代它立规则**。
判定：**独立立卡，不进本卡。作者对。**
