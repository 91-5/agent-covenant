### 本卡要拆的条款（dp 裁定 + sir 已拍板）

**X-7.3 永久 FAIL = 条款设计错误**

dp 分离出两个被捆在一起的目标：**可复现性**（manifest）与**安全性**（sandbox）。原条款把两者绑定，导致 M1 复算永久 `PROVISIONAL`——而 PROVISIONAL 的唯一成因是**安全边界缺失**，不是数值不可信。

sir 已拍板拆分：

| 门 | 内容 | 无沙箱可否 PASS | 状态映射 |
|---|---|---|---|
| **X-7.3a 环境可复现** | manifest 含 `python_version` / `platform_fingerprint` / `dependency_hashes`（pip freeze + 包文件哈希）/ `locale-timezone` / `env_whitelist` / `fixtures_sha256`，且与 `seal.json` 一致 | **可** | 全在位 → a = PASS |
| **X-7.3b 隔离安全** | 容器/VM 边界证明 | 不可（须 L2） | L2 → PASS；L1 → **CONDITIONAL**（披露后可用于 PROVISIONAL-L1）；L0 → FAIL |
| **X-7.3c 非确定性** | L0：判级器自身同输入 3 次逐字节相同；L1：命令 3 次比对（须注明未隔离） | **a. L0 可；b. L1 可** | `UNMEASURED` 不得当 ≤0.05 |

**M1 状态映射**：`a=PASS ∧ b=CONDITIONAL ∧ c≤0.05` → `M1 = PROVISIONAL-L1`（可用，须披露）；`b=FAIL` → 维持 `PROVISIONAL`。

**sir 已拍板 L2 挂账**：L2 真沙箱（Windows Sandbox / VM）本轮不立项。理由（dp）：它只解锁 X-7.3b 与恶意命令安全，而当前所有结论均已被 `independence_satisfied=false` 降级为方向诊断；在方向诊断精度下为不改变任何读数符号的安全属性付容器成本，收益不成立。

## Review questions

1. 「原文保留 + 勘误表 + 行内标记」这套审计连续性做法，是否比「原地直接改对」更适合一个已 PASS 并合入的报告？还是说保留错误的原文反而会误导后来读者（只读正文不读勘误表）？
2. `report_lint.py` 的检查是**词表匹配**（禁用「判别力为负」「完全缺失」等短语）。这种基于禁词的做法是否可被改写绕过（换成同义表述）？如果会，机械 lint 的实际价值是什么——防疏忽还是防规避？
3. 本卡把 `docs/eval-report-r15-truth.md` 列入自己的 Owned files 与 artifacts，使轮十六 verdict 成为该文件的新 authority。这是否构成「用后一个 verdict 覆盖前一个 verdict 的结论」？gate 的 `superseded by later verdict` 语义在此是否被滥用？
4. X-7.3' 拆 a/b/c 后，`b = CONDITIONAL` 允许 M1 升 `PROVISIONAL-L1` —— 这个「升级」是否实质降低了标准？换句话说：把「安全边界缺失」从阻断项降为披露项，会不会让后面某一轮悄悄把它当作已满足？
5. 本卡零新数据，但改动了已 PASS 报告。若后续有人只读轮十五 verdict 与报告，是否会得到「轮十五无瑕疵」的错误印象？勘误表是否应同时回写进 verdict 的 notes（那需要浮香重签）？
