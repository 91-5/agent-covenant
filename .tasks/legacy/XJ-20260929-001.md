## Context

A two-agent pilot (a small PowerShell tool, reviewed by a separate agent through a
different model) produced a set of hard-won collaboration rules and one
unpublished failure mode: a bare `TASK-002` card name was hijacked by a second
agent's identically-numbered internal task, and the review came back confident,
detailed, and about entirely the wrong artifact. See
`examples/deepfreeze-pilot/` and `postmortems.md` §PM-1.

The orchestration layer of the multi-agent field is saturated (70k★–293k★
incumbents). The layer this pilot accidentally proved a need for — *verdict
checking* — had, as far as we could find, no project above 5★. This task packages
what the pilot learned into a portable spec plus two dependency-free checkers.

## Constraints

- **Stdlib only** in `tools/`. A gate that needs a dependency install cannot run
  in a locked-down CI image, and then it is not a gate.
- **Fail closed, always.** A checker that crashes on hostile input is a bug, not
  a pass (`postmortems.md` §PM-6). Exit code 2 (usage) must never be read as pass.
- **No marketing claims.** Every capability in the README must resolve to a file
  in this repository, and the limitations in `PROTOCOL.md` §10 stay accurate as
  the project grows.
- Claims about third-party projects (star counts, maintenance status) carry the
  date they were observed and link to the source in `README.md`.
- This task's own author may not produce its own verdict.
