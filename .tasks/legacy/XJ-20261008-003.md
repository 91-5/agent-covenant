### 关于 P2-2 的设计取舍（作者判断，非照搬评审原话）

评审原话是「改为 CI 动态注入（`grep -c "^def test_" tests/*.py` 写入 README 固定锚点位置）」。**作者采纳其"消除手写数字"的目标，但调整实现**，理由两条：

- **不为 CI 写文件**：CI 改 README 会留下未提交 diff，在 PR 流程里是污染；且仓库 `gate.yml` 权限刻意限制为 `contents: read`，写文件需提权，与既有最小权限设计冲突。
- **不让 lint 改用 grep**：先实测确认 `grep '^\s*def test_'` 本仓 = **168**，与 unittest 权威数 **168** 一致（逐文件 19+58+91）。但这是**当前语料**的巧合（无参数化、无测试基类复用用例）。`check_stale_test_count` 已改用 `unittest` 真实发现（`_discover_test_count`），**不应退回脆弱的 grep 口径**——否则将来引入参数化测试即静默失准。

**采用方案**：本地脚本 `scripts/sync-test-count.py` 生成并写回 README 锚点 + lint 保持 unittest 权威校验。即"注入"发生在**人跑脚本时**，而非 CI。
