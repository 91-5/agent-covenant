## Deliverables

### D1 · `tools/link_card.py`（新建，stdlib only，Python 3.9+）

CLI 约定与 `gate.py` 一致：退出码 0=成功，1=业务错误，2=用法错误；`--help` 可用；错误信息可操作（说清缺什么、下一步做什么）。

用法：

```bash
python tools/link_card.py --card DFB-20261019-001 --verdict verdicts/DFB-20261019-001.verdict.json
python tools/link_card.py --card XJ-20261019-001 --verdict verdicts/XJ-20261019-001.verdict.json --freeze-dir /path/to/.freeze
```

参数：

- `--card`（必填）：卡号
- `--verdict`（必填）：verdict JSON 文件路径
- `--freeze-dir`（选填，默认 `.freeze`）：link 文件所在目录

行为（按顺序，每步失败即 fail-closed 退出 1）：

1. **卡号路径安全校验**：拒绝含路径分隔符（`/` `\`）、`..`、绝对路径前缀、空值的 `--card`。**不**做命名空间格式校验——那是 `lint_cards.py` 的职责，此处只防路径注入（防 link 文件名逃逸）
2. **定位 link 文件**：`<freeze-dir>/link-<card>.json`。不存在 → 退出 1，错误信息必须含「先运行 deepfreeze protect --card <卡号>」的可操作提示
3. **解析 verdict**：JSON 可解析；`id` 字段存在且**等于** `--card` 值（不等 → 退出 1，防止绑错 verdict）；`ts` 字段存在
4. **读出现有 link**：JSON 可解析（损坏 → 退出 1，**不得**覆盖重写——那是销毁快照绑定）；提取既有全部字段。读取用 `utf-8-sig`：deepfreeze 以 PowerShell `Set-Content -Encoding UTF8` 写出的 link 带 BOM 前缀，严格 utf-8 解码虽不报错但会把 BOM 保留为 U+FEFF 字符、导致下游 `json.loads` 失败，故在解码层剥除（无 BOM 的正常 UTF-8 读行为不变）
5. **计算 verdict 文件 SHA256**：对 verdict 文件**原始字节**计算（`hashlib.sha256`，流式读取）
6. **合并写入**：保留 link 既有全部字段（尤其是 snap 组），仅设置/覆盖：
   - `verdict_ts` = verdict 的 `ts`
   - `verdict_sha256` = 第 5 步计算的十六进制摘要
   - `verifier` = verdict 的 `verifier` 字段（缺失则跳过该字段，不报错）
   - `updated_at` = 当前 UTC 时间，ISO 8601 带 `Z`（如 `2026-10-19T07:30:00Z`）
   - **禁止**写任何 `snap_*` / `card` / `source` / `created_at` 字段（deepfreeze 的单写字段组）
7. **原子写回**：同目录临时文件 + `os.replace`（Windows 上 os.replace 原子覆盖；防止 deepfreeze 读到半截 link）。临时文件用 `tempfile.mkstemp(dir=freeze_dir)`，失败时清理
8. 成功时 stdout 一行摘要：`linked <card>: snap_ts=<...> verdict_ts=<...>`（snap_ts 从既有 link 读，没有则显示 `-`）

重复运行语义：同卡第二次回写（rework 后的新 verdict）→ 覆盖 `verdict_*` 字段，last-write-wins，与 deepfreeze 侧「重复 protect 覆盖 snap 字段」语义对称。
