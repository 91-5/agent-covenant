## Context

XJ-20261027-001 把判定密封进包后，浮香审出两个残留面（她称为「纵深防御非漏洞」，但值得收口）：

**A1｜密封判定与产物之间无交叉校验**
`report.judge_package` 一旦发现 `judgements-blind.json` 就直接返回、**不再读 `products/`**。若打包之后有人改了产物文件，密封判定会**静默过时**——报告仍按旧判定出数，与磁盘上的产物不再对应。当前唯一防线是 `seal_run.py` 对**运行目录**（不是包）做的 SHA 清单，两者未联动。

**A2｜漂移只有 stderr 一行**
`--allow-drift` 时只在 stderr 打 `[DRIFT]`。正文（报告/解盲附录）里没有任何痕迹，容易被只读正文的人当作单值引用——这正是「−50.0% 与 −48.3% 被当成同一件事」的入口。

## Deliverables

- **D1（A1）产物封签**：`blind.build_package` 在 `manifest.json` 内写入 `product_sha256`（`{P码: sha256}`，流式哈希）
  - `report` 侧新增 `check_product_seal(package_dir)`：逐文件比对，**任何不一致即 `ValueError` 硬停**（这不是 drift，是篡改/污染，不给 `--allow-drift` 开关）
  - 无 `product_sha256` 的旧包（历史三轮）跳过校验并在报告头注明「本包无产物封签，交叉校验未启用」
- **D2（A2）正文追双数字**：`blind_report` / `unblind_fragment` 的**头部**在包带 `root-state.json` 时自动写入：
  - `判定快照：git_head=<前12位>（dirty=<bool>），本报告全部数字为该状态下的密封判定值`
  - 若发生漂移（`--allow-drift`）→ 追加一行 `⚠ 漂移：打包时 <head> → 现在 <head>；本数字仍为打包时刻值，与当前仓库不可比`
  - 该行为**无条件自动**（不依赖调用方记得加参数）
- **D3** `docs/eval-runner-protocol.md` §12.5 补两条：①密封判定与产物封签须成对引用；②正文自动携带快照与漂移行
- **D4** `tests/test_eval_harness.py` 新测试：
  - 产物 1 字节改动 → `blind_report` 抛 `ValueError`（且 `allow_drift=True` 也拦）
  - 密封包报告头含 `判定快照`
  - 漂移 + `allow_drift` → 正文含 `⚠ 漂移` 行（不只是 stderr）
  - 旧包 → 头注「无产物封签」
- **D5** `artifacts.json` 登记
- **D6（A3 调查）** `docs/eval-runner-protocol.md` §12.6：第二轮 158/258 调查记录
  - 方法：同包连跑 3 次，比对「汇总 vs 自表逐行和」并与 `claims.json` 对账
  - 结果：**3/3 全为 258 且内部自洽** → 158 **不可复现**，故不声称已修复
  - 附带发现：该旧包 E2 已由 75 涨到 81（无密封判定 → 每次现场重判 → 仓库前进即漂移），实证了 §12.1 的机制
  - 处置：不追到底（不可复现时改代码等于瞎猜），以「护栏 + 新包密封 + 文档记录」收口
