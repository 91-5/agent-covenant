## The three questions I was asked to push hardest on

### RQ1 — Is Q4's default (`--artifact-map` → `./artifacts.json`) a fix or a scope error?

**A fix, with one thin residual edge.** The trade is right because the failure mode of a
remembered flag is silent (PM-10) while the failure mode of the default is loud-and-narrow:
it only fires when linting a project that both contains a parseable `artifacts.json` *and*
has a claim-surface file absent from the newest id — and it emits a WARN, not an error. An
unrelated `artifacts.json` that fails to parse exits with `EXIT_USAGE`, which is loud. I
would still add one sentence of observability (see Observations), because "a rule you did
not ask for" should announce itself.

### RQ2 — Is `_FailedTest`-by-class-name stable enough?

**Stable enough, and the failure mode is acceptable — but it is currently unlocked.**
`unittest.loader._FailedTest` is private and unversioned, yet unchanged across CPython
3.2→3.13 and mirrored by PyPy; and if the name ever drifts, the worst outcome is a missed
WARN, never a wrong count (discovery exceptions are already caught; a vanilla
"nothing to compare" is the pre-PM-11 status quo). What bothers me: the string appears
**zero times** in the test suite — the trigger path is exercised end-to-end via a real
broken import, but nothing pins the class-name contract itself. Hoist it to a module
constant (`_FAILED_TEST_CLASS_NAME`) and add one test that injects a fake placeholder
named `_FailedTest` into a suite. Non-blocking; the design is sound.

### RQ3 — Was FAIL the right verdict for round 5 (B1)?

**Yes, blocking was correct.** Three reasons, in order of weight:

1. **Direction.** The false sentence claimed *more* diligence than existed — an
   overstatement, in the changelog, about the project's own subject matter. That is R3
   aimed inward, and it is precisely the class this protocol exists to catch. A wrong
   command is a typo; a false completion claim is an evidence defect.
2. **CONDITIONAL would have lauded the wrong thing.** CONDITIONAL's semantics are "fix
   these and re-run" — usable when the work is incomplete but honest. Here the *claim*
   was the defect; accepting it conditionally would have signalled that this project
   settles false claims with paperwork.
3. **The payoff is already on the record.** Round 6 (this round) is what a FAIL bought:
   search-verified eradication, an in-place annotated false claim instead of a tidy one,
   and PM-11 written without a defence. That is the evidence chain working.

Precision nit, non-blocking: the 006 blocker text says it "falsifies the round's
cold-start acceptance criterion (both languages)". The 006 card's Acceptance states
commands, not a cold-start sentence. The blocker stands on the false-claim leg alone;
trim the second leg's wording next time.
