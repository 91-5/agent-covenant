### C-2 · 弃权偏置的**真因不是判级器偏置，是仪器定义缺口**（实测更正）

dp 裁定把 R10_ANCHOR 层的 71.67% 弃权归因为「judge 仪器对该层的偏置性不可判」。Orchestrator 逐条定位后**更正**这一表述：

- **60 条 PARSE_FAIL 全部**来自轮十 `round10-custody/gate0-claims.json` 的**「无证据行」样本**：证据行形如 `证据：（缺字段）`，**没有 `cmd=`、没有 `ref=`、没有 anchors**（`tools/eval/independent_judge.py::_parse_case` 实测：这类样本 `cmd=None ref=None anchors=[]`，证据行非空故不走 PARSE_FAIL 早退，但 `_reproduce` 无可执行命令 → 落 PARSE_FAIL）。
- **400 条样本中 239 条没有 `cmd=`**，分布为 `ref_ok 48 / ref_missing 48 / goldset_text 48 / incomplete 30 / no_evidence 30 / cwd_probe 18 / dotfile_claim 17` —— 即**独立判级器只对 161 条 cmd 样本有完整判级路径**，其余 7 层共 239 条（59.75%）走的是「无命令可复现」分支。
- **结论**：这 60 条不是「执行者做错」，也不是「判级器对某层有偏置」，而是**独立判级 rubric v2 未定义「结构上无证据可复现」这一类样本的处置**（rubric v2 要求显式锚点、无锚点 → INSUFFICIENT；无命令 → PARSE_FAIL）。**这是仪器定义缺口，可修，且修得干净**——处置方式须由 §19 冻结（见 D0）。
- **控制变量**：HOLDOUT 层 88 条 SUPPORT 对 0 条 PARSE_FAIL，说明这不是判级能力的普遍不足，而是**分层样本构成差异**（R10_ANCHOR 源自轮十 gate0-claims，HOLDOUT 源自 30 个 seed 任务）。

### C-3 · ADV-2 的真因：`exit_source` 全部为 adapter 是**采集方式**问题，不是不可得

`tools/eval/gate_metrics.py::run_r11` 实测逻辑：读取 `r10-gate-input.json::field_semantics.exit_code`，该字段逐字声明是「a mechanical map over flags/detail, NOT an independent OS process exit code」→ 判定 `mechanical = True` → **210/210 全部标 `exit_source = adapter`** → §18 条款 11 排除后主样本集 0 条 → `precision/recall = null`。

**而 `tools/eval/exit_fixture.py` 已经具备真实 OS 退出码采集能力**（三态 os/adapter/launch_failed，夹具 10/10 已通过，见轮十一 D5）。也就是说：**真实 OS 观测能力已存在，只是门重跑没有用它**。这是采集管线未接通，不是能力缺失。

### C-4 · 轮九 ADV-1 环境隔离条款至今未闭合（实测）
