第 3 项是本卡的直接触发，由 `XJ-20261004-003` 的独立评审（Agnes）指出，并给出一个**我原先搞错的判定**：

> §6.1 supersession 是**新鲜度机制**（一份更新且更高的权威退役同一文件上的旧 `STALE` finding），
> **不是**「重判已消解的 `CONDITIONAL`」的机制。硬套是**范畴错误**。

我核对协议确认她对：§6.1 原文讲的是「later id … on **that file** … earlier finding becomes
`SUPERSEDED`」，机制作用于**同一文件的新鲜度**，与「某卡的条件是否已被满足」是两回事。

**所以现在需要的是一套新的、显式的「消解引用」schema。**

## Deliverables

### D1 —— 消解关系由谁承载？

**要裁决的是**：CONDITIONAL 的条件被满足后，这个「已消解」的事实记在哪里？

候选（请评审方判断，作者倾向 **(a)**）：

| 方案 | 描述 | 作者初判 |
|---|---|---|
| **(a)** | **修复卡的 verdict 加 `unblocks: "<原卡id>.<conditionid>"`**，原 verdict 一字不动 | ✅ 倾向采纳 |
| (b) | 在原 verdict 上加 `closed_by: "<修复卡id>"` 字段 | 需改历史 verdict 文件 |

| (d) | 重发同 id 的 `PASS` verdict | **已知有害**：两份同 id verdict 让 §6.1 无法区分新旧权威 |

### D2 —— 历史 verdict 可变还是不可变？

`verdicts/` 下的 verdict 是**审计正本**。本仓已有先例（§8 `[0.1.17]`：归档卡的 verdict 保留且不动）。
若选 (a)，原 verdict 天然不可变；若选 (b)，就要定义「哪些字段可增补、增补是否破坏审计」。

### D3 —— `self_signed` 的表达

`XJ-20261003-001` 是 `verifier: jarvis@agent-covenant`、`independent: true`，而被审的 §6.2
正是同一人所写。当前 `independent` 是**自由布尔**（谁都能填 `true`）。要裁决：

- (i) 保留 `independent` 不变，**另加 `self_signed: true`** 显式标注；
- (ii) 把 `independent` 改为**派生字段**（由门禁从 `verifier` 与 commit 作者的关系推出）；
- (iii) 两者都要。

**注意**：本 ADR **只定 schema**，**不实现**机检。实现是后续卡（见 Out of scope）。

### D4 —— 与 §6.1 的边界

必须明写：**消解引用 ≠ supersession**。前者答「一个条件是否已被满足」，后者答「一份结论是否仍新鲜」。
两者独立，不得互相顶替。这条是 `XJ-20261004-003` 直接点名的范畴错误，必须在 ADR 里固化，防再犯。

## Review questions

1. **D1 选 (a) 还是 (b)？** 我倾向 (a)（修复卡承载 `unblocks`，历史 verdict 不动），
   理由是它符合本仓「历史 verdict 是审计正本」的既有原则。但 (a) 有个弱点：
   **`unblocks` 写在修复卡上，意味着「谁被消解」这件事不在被消解那张卡上**——
   将来查 `XJ-20261003-001` 时，得反向搜全目录才知道 C1 已闭合。这算不算新的可发现性缺陷？
2. **同一条件被两张修复卡同时声称消解**（`unblocks` 值相同）要不要检测？怎么检测？
3. **`self_signed`（D3）该不该阻塞合并？** 我倾向**不阻塞、只标注**——因为它是
   「如实记账」而非「判罚」（§6.2 P2 允许诚实的变更记录）。但若只标注不阻塞，
   `XJ-20261003-001` 那类自签 verdict 仍会被当权威引用，标注能不能真的防住？
4. **D4 的边界要不要写成可机检的断言**？（例如：`SUPERSEDED` 只能由同一文件的
   later verdict 产生，`unblocks` 不得触发 `SUPERSEDED`。）还是留在散文层？
5. **`ADR-0002` 定稿后，`ADR-0001` 的 Revisit-trigger 第 3 条要不要指向它？**
   （`ADR-0001` 第 3 条讲「card schema 因故要变时」，本 ADR 正是那个变更。）
