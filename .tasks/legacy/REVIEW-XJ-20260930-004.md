## 本轮 4 问

### Q1. PM-5 改写后的事实正确性

**改写正确。** 原文 "Not enforced by a tool" → 现文 "Partially enforced: write-time race 不可 lint；
planning-stage declaration 可 lint (`OWNED_FILES_CONFLICT`)"。两个半句都准确。

第三种情况：**未声明所有权的并发写入。** 如果两个 agent 都没有在 `## Owned files` 里声明
某个文件，linter 无从比较（无声明即无冲突可报）。这不是 PM-5 的遗漏，是
`OWNED_FILES_CONFLICT` 规则的能力边界——它检测的是"两个声明冲突"，不是"无声明就乱写"。
后者属于 R2 的组织性纪律，已在 §10 "not machine-checkable" 里覆盖。

结论：**没有实质遗漏，但可加一句明示边界。** 不影响 PASS。

### Q2. `REVIEW-REQUEST-*` 豁免是否开错了口子

**没有开错。** 原因：

1. **语义正确：** REQUEST 是 handover 指令（"请你审这个，写到那个路径"），按定义不携带 verdict。
   它不是评审结果，是评审触发器。结果文件（`REVIEW-*.md` + `*.verdict.json`）仍受完整 lint。
2. **不可伪装：** 任务卡不会自然命名成 `REVIEW-REQUEST-*`。如果一个文件叫
   `REVIEW-REQUEST-XJ-20260930-004.md`，它的语义就是"这是一个请求"。你不能把交付物
   伪装成请求来绕过 verdict 要求——因为交付物（code、tests、protocol）不在这个目录里。
3. **残余检查仍在：** 豁免只跳过 `REVIEW_MISSING_VERDICT_LINE` 和 `REVIEW_MISSING_BLOCKERS`。
   命名规则（NAMESPACE）、bare-task-ref、owned-files 规则全部仍然适用。
4. **linter 不是安全边界：** 它是质量提示工具，不是权限系统。即使有人故意命名规避，
   门禁（gate.py）仍然独立检查 verdict 文件，linter 被绕过不影响 gate 的判断。

### Q3. L2 严重度指引——还有哪条 WARN 在 L2 下必须是 ERROR？

已列两条（`OWNED_FILES_CONFLICT`、`VERDICT_WITHOUT_REVIEW`）之外，我推荐补第三条：

**`ORPHAN_VERDICT` 在 L2 下应为 ERROR。** 理由：一个 verdict 文件没有对应的 task card，
意味着证据链断裂（"谁判了这个？"不可回答）。在 L2（无人值守 CI）下，断链的 verdict
无法被审计追溯。这与 `VERDICT_WITHOUT_REVIEW` 是对称的：一个是有 verdict 没 card，
一个是有 card 没 verdict；另一个是有 verdict 没 card。

次选：`TASK_MISSING_REVIEW_QUESTIONS`。在 L2 下没有 adversarial brief 的 task card
直接导致 rubber-stamp 风险（PM-3）。但这条比 ORPHAN_VERDICT 弱——它只降低审查质量，
不破坏证据链。
