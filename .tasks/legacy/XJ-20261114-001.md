### 缺口是 fail-open，不是 fail-closed

判定路径（`tools/lint_cards.py:821-850`）：

```
targeted = card["protected_assets_targeted"]
unknown  = [t for t in targeted if t not in PROTECTED]   # -> EVO_PROTECTED_ASSET_UNKNOWN (WARN)
hit      = [t for t in targeted if t in PROTECTED]
if not hit: continue                                      # <- 元组缺第 6 项时走这里
if changes and approval: EVO_PROTECTED_ASSET_TOUCHED (WARN)
else:                   EVO_PROTECTED_ASSET_TOUCHED (ERROR)
```

一张**只声明第 6 项资产**、且缺 `protected_assets_changes` + `sir_approval` 的 EVO 卡：`hit = []` → `continue` → **根本不产出 `EVO_PROTECTED_ASSET_TOUCHED`（ERROR 分支永不执行）**，只剩一条 `EVO_PROTECTED_ASSET_UNKNOWN`（WARN，提示「不在受保护清单里，请检查拼写」）。

即：**AGENTS.md 声明为受保护的第 6 项，在 linter 眼里是不设防的**——一张自授权改写合并判定器的卡会以「拼写错误」的口吻被放过，而规则文本要求它被 ERROR 阻断。这是新增受保护资产落地时强制层未同步造成的实质缺口（fail-open），不是文字瑕疵。
