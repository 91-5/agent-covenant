## Answers to the review questions

### Q1（最关键）—— D1 选 (a) 还是 (b)？反向可发现性代价值不值得换不可变性？

**维持 (a)。我不推翻，理由不是「可发现性无所谓」，而是这笔账 ADR 已经算过并留了
重开开关：**

- 不可变性不是审美，是本仓**付过两次学费的既有原则**：§8 `[0.1.17]` 刚把「归档卡
  verdict 一并删」改成「verdict 是证据，不随卡销毁」；§6.1 的 "reported, never dropped"
  同向。选 (b)（在原 verdict 上写 `closed_by`）买的是正向可发现性，代价是**允许事后
  编辑审计正本**——恰是 §8 与 §6.1 同时设防的失败类。ADR 原文「the repository has
  already paid for a version of it」与 §8 CHANGELOG 条目对得上，我认账。
- (a) 的弱点真实但量级可控：本仓 verdict 是个位数到两位数，反向 grep 全目录成本极低；
  卡片规模上来后它变成可机检的查询问题（正向索引），不需要回头破不可变性。
- **决定性的：Revisit-trigger 第 3 条已把弱点写成退出条件**——「a consumer repo asks
  for closure to be queryable in one direction (card → its discharge) … the trade-off
  deserves re-examination」。作者没有赌「可发现性永远不是问题」，而是写死了「一旦
  付出代价就重开」。这是决策文档该有的样子。

**Q1 结论：维持 (a)。** 弱点是「被显式记账、带重开条件的已知成本」，不是致命缺陷。
我把它写进 verdict conditions，确保后续实现卡不把它静默固化为永久状态。

### Q2 —— 同一条件被两张修复卡同时声称消解（`unblocks` 值相同），要不要检测？怎么检测？

**要检测；检测手段在后续机检卡，但 ADR 决策层现在必须承认这个失败模式存在。**

- 检测设计（后续卡实现，本卡 Constraint 1 禁改工具）：`tools/lint_cards.py` 扫
  `verdicts/` 全部 `unblocks` 值；两个**不同 id** 的 verdict 带同一个
  `<原卡id>.<条件id>` → **warning**（先记账、不阻塞）；若目标条件的原文已被改到不再
  接受该闭合 → **error**。
- **ADR 目前的缺口**：Consequences 只写了 `unblocks` is unenforced until a later card，
  但**没有点名「重复闭合」这个具体危险**（两张卡 `unblocks` 同一 condition）。
  Revisit-trigger 第 2 条的「three or more cards reference the same original condition」
  是**歧义**触发点，不是**危险**陈述；两张卡的 Q2 情形落在「三张才谈歧义」与「两张
  沉默」之间，没被覆盖。故记为 **Condition B1**：ADR 定稿在 Consequences 或
  Revisit-trigger 补一句「≥2 张 verdict 声称同一闭合为已知危险，仲裁归后续机检卡，
  在此之前 lint warning 记账」。这是决策层补全，不是要我现在写代码。

### Q3 —— `self_signed` 该不该阻塞合并？只标注、不阻塞的话，标注防不防得住被当独立权威？

**「不阻塞、只标注」作为 schema 层决策是对的；但按 ADR 目前的写法，这个标注防不住
`XJ-20261003-001` 类 verdict 继续被当独立权威引用——它是名片，不是门禁。记为
Condition B2。**

- 「不阻塞」合理：`self_signed` 是如实记账（§6.2 P2 的诚实变更记录精神），判罚属于
  门禁层而非 schema 层，ADR 不越权，这个边界画得对。
- 缺陷在机制：§6.1 的 valid-authority 判断目前按 `independent: true` 计算。在机检
  **读取** `self_signed` 之前，`self_signed: true` 的 verdict **仍满足
  valid-authority 的「independent」条，仍可当 supersession 的 successor 退役旧
  finding**。本 commit 的 `PROTOCOL.md` §6.1（A6 已证未改）全文没出现
  `self_signed`——只有 ADR 定义了它，而 ADR 只说「disqualifies … from being cited
  as independent authority」，**没写失效靠什么机制生效**。两种读法：
  - (i) **接进 §6.1 valid-authority 判断**：`self_signed: true` 视同
    `independent: false`，不退役任何东西。标注有牙齿；`XJ-20261003-001` 类自签
    verdict 停止当独立权威。
  - (ii) **纯文档层标注**：靠读者自识别；机器什么都不做。那么 Q3 的直白答案就是
    「防不住」，且 ADR 自己 Gains 段那句「`XJ-20261003-001` stops being citable as
    independent authority」**在读法 (ii) 下为假**——它要等到后续机检落地才为真。
- ADR 定稿必须在 D3 里二选一并写明。我推荐 (i)：一句话即「in §6.1's valid-authority
  bar, a verdict carrying `self_signed: true` is treated as `independent: false`; it
  retires nothing」——这是 schema 决策，不是工具实现。若作者选 (ii)，则
  Revisit-trigger 第 4 条的「relied upon as independent」判据必须写成**可机检**
  （哪个工具、什么时机发现），因为今天这条只靠人眼。

### Q4 —— D4 的边界（消解 ≠ 新鲜度）要不要写成可机检的断言？

**要——放在后续机检卡；但 ADR 应写明「此边界可机检、只是本卡不实现」，防止被读成
「本仓永远不机检 D4 边界」。**

- 散文层（ADR 已有，正确）：「§6.1 decides freshness, this ADR decides closure, and
  neither may substitute for the other.」边界陈述清楚，我认可。
- 机检层（后续卡，本卡 Out of scope）：`tests/test_gate.py` 加两条用例：
  1. **正例**：verdict 带 `unblocks` 但目标文件**无** later verdict → 原 verdict 的
     `STALE` 状态**不变**（闭合不触碰新鲜度）；
  2. **反例**：构造 `unblocks` 作用于同一文件的用例，断言 `unblocks` **永不**产生
     `SUPERSEDED`（只有该文件的 later valid authority 可以）——两条机制双向正交。
- 建议 ADR 补一句（一句，不写代码）：「D4 边界可机检，推迟给后续机检卡；一旦闭合被
  误用于产生 `SUPERSEDED`，触发 Revisit-trigger 第 1 条。」Revisit-trigger 第 1 条
  现在只写「an `unblocks` claim is found to be false」，把「边界被突破」并入其射程
  即闭环。

### Q5 —— `ADR-0001` 的 Revisit-trigger 第 3 条要不要指向 `ADR-0002`？

**要——作为 ADR-0001 的一条脚注，在 ADR-0002 被采纳时加。它不是本 ADR 正文的要求，
也不在本卡 Owned files 内（ADR-0001 不属于 XJ-20261004-004 的 owned 文件）。**

- ADR-0001 第 3 条：「the card schema changes for an unrelated reason … at which point
  adding acceptance ids is nearly free」。ADR-0002 正是该触发条件的活实例：
  `unblocks` / `self_signed` 都是新增 verdict 结构字段（schema 动了），而
  acceptance-id 迁移（ADR-0001 的推迟项）恰好在这个「白改 schema」的窗口里成本骤降——
  就是触发条描述的那个 cheap window。
- 建议文本（维护动作，sir 采纳 ADR-0002 后执行）：在 ADR-0001 第 3 条后附一句
  「*Instance: ADR-0002（若被采纳）即本条的活触发——verdict schema 字段动了而
  acceptance-id 变更没顺路搭车；窗口开着时重新给迁移估价。*」本 verdict 记为非
  阻塞 **Condition C3**，作为维护提醒，不进 gate 条件。
