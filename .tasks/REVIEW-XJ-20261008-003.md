## 独立取证（关键发现，超出作者自检范围）

**P3 的 `\x1e` 切分在"干净数据"上把 `commits_total` 翻倍——这是一处 2× 分母回归。**

`trailer_adoption` 用 `git log --format=%H%x1e%B%x1e`。git 对每个 commit 输出 `SHA, 0x1e, 完整message, 0x1e`，其中 **message 与下一个 commit 的 SHA 之间没有换行**（`%x1e` 终止符紧贴下一个 `%H`；整段拼接后形如 `sha\x1ecommits正文…\x1e\nsha\x1e…`，split 出的 message 段末尾带一个孤立 `\n` 段）。`raw.split("\x1e")` 之后**每个 commit 产生两个非空 chunk**（SHA 段 + message 段），于是 `commits_total` 恒为真实 commit 数的 2 倍：

- scratch 仓（3 个真实 commit，无 `\x1e` 脏数据）：`trailer_adoption` 返回 **`(6, 1, True)`**；`git rev-list --count` = **3**。
- 真实仓 `origin/master..HEAD`：`git rev-list --count` = **10**，但 `check_owned_files --json` 报 `commits_total: 20`（作者自检数据里那条 `trailer=0/16` 与本轮我实测的 `0/20` 同属该回归，随分支推进而增长）。

分子（`with_trailer`）**没有被翻倍**（trailer 行只落在 message 段、每 commit 一段），所以 50% 阈值算出的采纳率**系统性偏低 2×**——数据只会更难达标、不会误放行越界；但作为 GATED 前置证据，**源头数字本身就是错的**，不可入账。

**为何 185 tests 全绿也抓不到**：`tests/test_check_owned_files.py` 里所有触及 `trailer_adoption` 的用例（`test_trailer_adoption_below_half...`、`test_failed_measurement...`、`test_measured_zero...`）**全部 mock 掉 `check.trailer_adoption` 直接返回三态 tuple**，没有一条用例真正跑过 `git log --format=%H%x1e%B%x1e` 的 split 路径。真实 git 输出的 chunk 结构（2 chunk/commit）从未被任何测试见证。这是本卡主题"measurement must not lie about its own number"下最讽刺的一个洞：P2 修的是"未测伪装成 0/0"，P3 却造出了"测了但 20 冒充 10"——**同一个反模式换了张皮又回来了**。

## 逐项裁定

### P2 · not-measured 三态 —— ✅ 接受

- `trailer_adoption` 由 `(total, with_trailer)` 扩为 `(total, with_trailer, measured)`；git 失败 → `(0, 0, False)`。
- `evaluate` 的 git 失败分支（`changed_paths is None`）与 `trailer_adoption` 自身失败回落**都**显式落 `trailer_measured: false`，不再硬编码 `(0,0)` 冒充满额。
- `render_warn` 未测时打印 `trailer=NOT MEASURED`（而非 `0/0`），info 追加"could not measure, not 'nothing declared a trailer'"。
- 独立复核：两条新单测（`test_failed_measurement_is_labelled_not_shown_as_zero` / `test_measured_zero_is_not_labelled_as_unmeasured`）分别守住"未测"与"真 0/N"两个方向，边界对称，质量达标。

### P2-2 · 计数根因 + 有意偏离（本地脚本而非 CI 注入）—— ✅ 接受偏离

三条偏离理由逐条复核后**都成立**，且比评审原话更稳：

1. **CI 写文件污染 PR + 与 `contents: read` 最小权限冲突**——认可。`gate.yml` 刻意持 read，给 writer 提权是权限面扩张，与项目一贯的最小权限设计矛盾。本地脚本把"注入"挪到人跑脚本的瞬间，不动 CI 权限，取舍合理。
2. **`grep '^\s*def test_'` 是巧合不是口径**——这是**本卡最正确的一条判断**。作者实测 grep=168 与 unittest 权威数一致，但那是"本仓当前无参数化、无基类复用"的语料巧合；`lint_cards` 已用 `_discover_test_count`（unittest 真实发现）做校验，sync 若退回 grep 口径就出现"写数工具与校验器两套口径"，将来引入参数化测试即**静默失准**。`real_test_count()` 复用校验器自己的发现口径（`_load_linter(). _discover_test_count`）是"同一口径写数与验数"，对。
3. **锚点不免检**——认可且实测通过（scratch 写 999 → `STALE_TEST_COUNT` ERROR）。锚点只是"不再手写"的载体，数字仍被读回校验；`tests/test_lint_cards.py::test_anchor_is_reported_once_not_twice` 还守住"锚点行不与 prose 正则双计"。

### P3 · 解析对齐 —— ❌ 阻断（2× 分母回归）

对齐的**目标**（消除 `\x00`/`\x01` 与逐行 TRAILER_RE 的两套判据）正确，行级语义也确已对齐；但**记录级分隔选错了**。

- 现状：`raw.split("\x1e")` 每 commit 2 个非空 chunk（SHA 段 + message 段），`commits_total` 恒 2×。
- 后果：GATED 判据 `commits_with_trailer / commits_total` 分母被系统性放大 2×，影子期采纳率数据**从源头错**（偏保守方向，不会误放行，但不可作为 GATED 前置证据入账）。
- **修复方向（给 OpenCode，非我越权代改）**，二选一：
  - (a) 分母改用 `git rev-list --count <base>..<head>` 独立取真数；`git log --format=%B`（只取 message）仅用于判断"哪些 commit 带 trailer"（按 commit 序对齐行块）；
  - (b) 一条 git 命令同时取 (总, 带trailer)：用**每 commit 恰好出现一次**的记录定界（如 `--format=%x00%H%x00%B%x00` 全量 0x00 包界，split 后按"首行是 40 位 SHA 的 chunk"计数，而非裸 split 计数）。核心判据只有一条：**`commits_total` 必须等于 `git rev-list --count`**。
- **必须补的回归测试**：一条真 `git init` + 3 commit（其一带 trailer）的**集成测试**，断言 `trailer_adoption(...) == (3, 1, True)` 且 `total == rev-list --count`。没有它，mock-only 的测试面就永远抓不到这类"真实输出结构"回归——**这是 74026c7 能带病 185 绿上线的根因**。

## 四个对抗性问题裁定

**Q1 · `\x1e` 作提交间分隔，body 真含 `\x1e` 会怎样？残余脆弱性比原 `\x01` 方案更好，还是只是换了地方？**

- 裁定：**比 `\x01` 方案更糟，且不是"body 含 `\x1e` 才触发"的边缘问题——干净数据上就已经错了。**
- 原 `\x01` 方案：body 含 `\x01` 才撕裂，最坏 `commits_total` 虚增 1（008 评审点 1 已判"概率极低、代价上限是采纳率偏噪"）。
- 新 `\x1e` 方案：`git log --format` 的终止符紧贴下一个 SHA、中间无换行，**即使 body 完全干净**，split 也恒产出 2 chunk/commit——从"低概率脏数据撕裂"升级为"恒 2× 系统性错误"。**不是换地方，是换了个更差的地方。** Q1 的裁定直接构成 P3 阻断项的独立佐证。
- 补充：body 若真含 `\x1e`，问题不会更严重（已经恒 2×），所以**不必**为脏数据另设护栏；先把"每 commit 恰好一个记录"的结构修对即可。

**Q2 · not-measured 三态：`metrics` 结构够表达吗，还是该在 `info` 里也强制出现一行？**

- 裁定：**`metrics.trailer_measured` 够机器消费，`info` 的显式行也应当保留——双轨各司其职，本卡做得对，无需再加第三处强制。**
- `metrics` 字段给下游程序/GATED 判据读（`trailer_measured: false` 可被 gate 逻辑硬引用）；`info` 行给人读的报告层。两层**不同步**才是真风险，本卡让二者同步体现（未测 → `render_warn` 打 `trailer=NOT MEASURED` + info 追加说明行；metrics 同步 `false`），满足"调用方能区分 0/0 满额 vs 未测"。

**Q3 · 锚点方案是否真消除根因，还是把"手写数字"换成"记得跑脚本"？lint 能否发现"锚点存在但从未同步过"？**

- 裁定：**诚实答案：消除了"两处 README 各手写一份、加一个测试双烂"的最痛根因（双写 + 手写 + 静默腐烂）；"人会忘跑脚本"这一层没有也不可能被消除——但 lint 恰恰不需要发现"从未同步"这件事，它只需要发现"不同步"。**
- 关键辨析："锚点存在但从未同步过"与"数字同步对了"在 lint 眼里**不可区分，也不需同意区分**。lint 判据是"锚点数字 == unittest 实数"：实数一变而你没跑脚本，锚点即 stale，`STALE_TEST_COUNT` 必报（实测 999 → 拦截）。**漏跑脚本的唯一可观测后果（数字腐烂）被 lint 100% 捕获**；至于"同步这个动作本身没做过"没有独立错误状态，不值得单列。
- 结论：根因确已消除，"记得跑脚本"残留的是**流程纪律**，但它**不再能悄悄失败**——漏跑必被 lint 拦，这正是本卡目标本身。
- **唯一残留风险（P3 级纪律提醒，非阻断）**：若未来新增第三处也写计数（如 CHANGELOG 快照、某 docs 页），而 `COUNTED_CLAIM_FILES` 只枚举两个 README，那处声明就游离在锚点机制之外。建议 GATED 前把"所有计数声明文件"收敛到单一枚举源。

**Q4 · 本卡同时动 3 个关注点（P3/P2/P2-2），是否该拆三轮以避免"一卡一主题"稀释？**

- 裁定：**这一轮不该拆——不是"三件事都能合"，而是"三件事共享一个判据主题，且拆开反而会把 P3 的缺陷藏得更深"。**
- 支撑：74026c7 的 message 自己点破了共同主题——"a measurement must not be able to lie about itself"。P2（别把未测谎报成满额）、P2-2（别让手写数字静默腐烂）、P3（别让同一 body 被两套判据判出两个结果）都是"测量自我诚实"的三个侧面，**同主题下合入是收敛而非稀释**。
- 反向风险已被 P3 的现实击中：正因为合在一张卡，P3 的 2× 回归**夹在**两个正确交付（P2/P2-2）里，若整卡一律 APPROVE 会被一起放行。故我裁定 **CONDITIONAL**（P2+P2-2 可先入册，P3 定向修复后重出）而非整卡 APPROVE/FAIL——**把"该不该拆"转化为"用 CONDITIONAL 精确圈住有缺陷的那一块"**，既保住 P2/P2-2 的合入，又不让 P3 被主题统一性掩护过去。
- 给后续卡的建议："一卡一主题"应理解为"**一卡一个可独立验收的判据面**"，而非"一卡一个文件改动集"。本卡主题成立（测量自我诚实），不强制拆；但任何后续卡若把"已验证交付"与"未验证交付"塞进同一 commit，verifier 必须能用 CONDITIONAL 单块圈住未验证项——本评审即为该机制的样例。
