## Judgment process — including the reversal

**First reading: PASS, 0 blockers, 3 advisories.** I had verified the mechanics of the fix and
found them sound — ledger-only scope (`git diff 9928bec^ 9928bec -- tools tests` empty; the
286-line tools/tests delta between 6477b4c and 9928bec belongs to e75ea0f, the 0.1.9 round
itself), 95/95 tests, §6.1 correctly placed with §6 item 7 pointing at it, the blockquote
method matching the 006/008 tradition, the 011 verdict untouched. I filed the numbers problem
as **A1** ("41 is a historical figure, unreachable now, but the mechanism narrative is true and
the projection is arithmetically derivable") and **A2** (the request card labels the
post-verdict 6-violation state "before your verdict lands" — measured pre-verdict is 17). That
reading treated "unreachable" as a property of time rather than of the claim.

**What the addendum's evidence changed.** Two things, one factual and one structural.

1. *Factual:* a clean-checkout run at 9928bec — the exact command a reader following the
   constraint "reproducible by running the gate at the recorded commit" would run — returns
   17/31, matching none of the three figures. I had independently measured 17/31 in the
   working tree and had not noticed that this contradicts all three numbers *simultaneously*,
   including the two I had not flagged. My A1 covered one figure; the defect covers the label.
2. *Structural:* my derived post-verdict advisory count (42) disagreed with the ledger's 40,
   and I had read that disagreement as tolerable because "the projection is derivable". The
   addendum forced the right question: derivable *to what*? To 42. The ledger says 40. A
   projection that names a state, attached to a state that never occurs, is not a projection —
   it is a wrong number about the future.

**Why the 011 standard reaches a wrong number — the question the addendum put to me.** 011
B1-i failed this project on "figures that were merely unreachable". If unreachable fails and
wrong passes, then the rule reduces to: inventing numbers is fatal, miscounting real ones is
not. That is backwards. An unreachable figure makes a claim no reader can check; a wrong
figure makes a claim a reader can check *and refute* — it is strictly more falsifiable, and in
a project whose premise is that records can be false, more dangerous, because it wears the
clothes of a verified number. The 011 standard ("falsifiable assertions about the gate's own
output") does not distinguish how the assertion fails, only that it fails. B2 therefore sits
inside the 011 standard, and B1 — three unreachable figures under a headline claiming
reproducibility — *is* 011 B1-i again, one round later, in the very paragraph written to fix it.

**On my own error:** my first PASS rested on granting the author credit for the correction's
*method* while discounting its *arithmetic*. The addendum did not give me new principles; it
gave me a run. The principle was already in my own 011 verdict. This is the fourth time this
repository has caught a false claim in its own record, and the first time the false claim was
mine to catch in advance — I had measured 17/31 pre-verdict and derived 42 post-verdict, and
still wrote "advisory". The lesson for the reviewer is the same one the project keeps teaching
its author: a figure you did not run is a figure you did not verify.
