## 6 条 Review Questions 逐条裁定

### RQ1 门禁闭环 → 见上。裁定 = CONDITIONAL（(a) 的有保留变体），C1/C2/C3 三条 condition。

### RQ2 `--require-link` NOTICE 的「静默误导」
`--require` 子集模式下点名集合外 id → 只发 stderr NOTICE（不阻断）。**裁定：当前 NOTICE 设计正确，P3 记录不阻断。** 理由：NOTICE 已消除「完全静默」，且 docstring + commit message 明写「A `--require-link` id not in the checked set can never be examined」。若升级为 blocking 会误伤：`--require-link X` + `--no-link-check`（关整族时不该因「你没检查 X」报错）+ glob 模式下 `--require-link` 传一个 verdict 尚未落盘的合法中间态（那应走 MISSING_VERDICT 而非 LINK 码）。**若担心「点名者以为强制生效了」，更诚实的做法是加 `--strict-require-link` 开关把它升 blocking，而非默认阻断**——留作 P3 follow-up，本期不扩 0/1/2 语义。

### RQ3 `LINK_NOT_STAMPED` 漏报「verdict 存在但从未建链」
该规则只在「link 文件存在 + 无 verdict_sha256」时 WARN；「从未建链」（link 文件压根不存在）**不报**。但 `1d65895` 的 `check_link_not_stamped` 里 `if not link_path.is_file(): continue`——「无 link」被显式当「历史默认态」放过（test `test_verdict_without_any_link_is_silent` 坐实）；且 `.freeze/` 整个目录不存在时规则整条关闭（zero cost，镜像 gate 的 opt-in）。**裁定：这是有意的边界而非缺陷——「无 .freeze = 该仓没启用快照设施」应零噪音，与 gate 的「无 link 静默」同源。** 若将来要报「verdict 存在但从未建链」，须知道该仓**已启用** .freeze（有 state.json / 其它卡有 link）却此卡缺链，那是「半启用」探测，成本高于收益，P3 记录、不在本期。`.freeze` 被删/换 --freeze-dir 的漏报：当前 lint 无 --freeze-dir 参数、固定读 `<card-dir>/../.freeze`，与 gate 的 `--link-dir` 可移动语义不一致——**这是真实的语义漂移点**，但两者都默认 `.freeze`，只有用户显式 `--link-dir` 移动时 lint 才漏；P3 记录。

### RQ4 `_find_bash` 把「面向 Git for Windows」写死过强
**裁定：P1（=C1），这是本卡唯一的 must-fix。** 模块顶层 `BASH = _find_bash()` 无 try/except、无平台守卫，POSIX（CI ubuntu-latest）import 即 raise → 红 CI（已实测坐实）。修复（C1 建议 ①）：`if os.name == "posix": BASH = shutil.which("bash") or "bash"`。这既保 Windows 的「锁 Git bash、不回退 WSL 漂移」原意，又让 POSIX 裸 bash（Linux/macOS 上本就是对的）能跑。**「找不到就 RuntimeError 会让非 Windows 直接不可测」——成立，且比作者预期更重：不止 test_pre_push_hook 不可测，是 discover 整批 291 例都 import 失败。**

### RQ5 `--check-all-links` 文件名 id 无 verdict 是否该阻断
**实测：当前会阻断（报 LINK_UNREADABLE + 连带 LINK_TS_INVERTED），并非跳过。** 语义上对——「link 承诺了 verdict 却读不到字节」是断链，blocking 正确。缺陷只在**码名**：verdict 缺失应归 `LINK_VERDICT_MISSING`（verdict 族）而非 `LINK_UNREADABLE`（link 族），与 EVO RQ5 同族诚实度问题。P3，未来扩 LINK 码族时拆出专码；本期不改（改码名会动 5 码 blocking 的既定面）。

### RQ6 `DEEPFREEZE_SKIP_LINK_CHECK=1` 粒度
只跳 link 那步，lint/gate 照跑。**裁定：粒度合理，不阻断。** 理由：三步语义正交——lint 审卡面 schema/claim surface，gate 审 verdict 轮次，link 审可追溯链；开关名带 `DEEPFREEZE_` 前缀明确指向「快照-链接设施」而非「门禁」，与「lint 与 gate 是另一类检查」的边界自洽。若将来要分步开关可加 `DEEPFREEZE_SKIP_LINT`/`DEEPFREEZE_SKIP_GATE`，但当前只 link 步需要临时放行（「link 是已知 work-in-progress」的文档语义见 hook 注释），加两个开关是 YAGNI，P3。
