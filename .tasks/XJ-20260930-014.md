## Context

013 recorded four false figures in a row — 17/31, the 40-advisory projection, 7/42, and the
"same commit" conflation — all one defect: **the gate prints a number without saying which
directory produced it**. The three-coordinate rule (commit, command, CWD) was written into
PROTOCOL §10 as prose. Prose did not stop the author from violating it twice in the same round
that wrote it. 013's question 5 asked whether the rule should be enforced; sir's answer was to
open this round.

The enforcement boundary was chosen deliberately. **What is enforced: the output carries its
coordinates.** Every run now resolves the process CWD and binds it to the output — `cwd` and
a `split_run` flag in the JSON, a loud banner on human output when the run is split. **What
is not enforced: rejecting numbers.** Split runs are legitimate (CI jobs, cross-repo audits,
this project's own `--require` acceptance invocations), and a gate that refuses to count
where it cannot verify context is a gate nobody can run. The failure mode being guarded —
four bad figures — was not "the gate ran in the wrong place", it was "nobody noticed the
gate ran in the wrong place". Visibility closes that; refusal would break legitimate use.

## Deliverables

- `tools/gate.py` — `main()` resolves the CWD at startup. The JSON output gains `cwd` and
  `split_run` (true when the verdict directory or the artifact map lies outside the CWD's
  subtree). A split run prints `[CWD] ... counts may not describe the checkout you think you
  are testing` on stdout before findings, and a `(CWD context: ...)` line after the advisory
  count. Findings and exit codes are untouched in all cases.
- `tests/test_gate.py` — new `TestCwdContext` (4 tests): JSON carries the true CWD and
  `split_run: false` for a same-tree run; a split run warns on stdout; `--quiet` suppresses
  the banner; the banner never changes an exit code. 95 → 99 tests.
- `PROTOCOL.md` — §10 item 7 now states the output contract (what the gate reports, and that
  the banner is advisory).
- `artifacts.json` — new `XJ-20260930-014` key.
- `.tasks/XJ-20260930-014.md` — this card.

## Constraints

- **No finding semantics change.** `evaluate`, `_check_*`, `_successor_candidates` and
  `_superseded_by` are untouched; the verdict schema is untouched; exit codes are untouched.
  A reviewer who approved the pre-014 gate's behaviour on a same-tree run must see identical
  findings now.
- **The banner must never decide anything.** It is a coordinate, not a check. If a future
  round wants a hard failure on split runs, that is a new rule requiring its own round and
  its own laundering analysis.
- **Known gap stated, not buried:** `split_run` compares the CWD against the verdict
  directory and the map file — not against where the map's *entries* resolve. A map with
  absolute paths to a third tree, run under the CWD, reports `split_run: false`. Closing it
  means resolving every mapped path before counting; deferred with the reason recorded, not
  silently skipped.
- **013 is still open.** This round does not amend 013's card, its request, or the `[0.1.9]`
  paragraph under review. If 013 returns FAIL on prose, the fix is 015's problem, not an
  in-place edit here.
