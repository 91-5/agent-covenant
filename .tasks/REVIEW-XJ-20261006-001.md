## Answers to the review questions

**Q1 —— 被引卡无 verdict 时双 WARN 算不算噪音？**

**不算。受众与触发条件都不同。** `VERDICT_WITHOUT_REVIEW` 对**读卡的人**说「这张卡
还没有 verdict」；`UNBLOCKS_DANGLING` 的「cannot be verified」对**读 verdict 引用链的
人**说「你这条具体引用（哪条 ref、哪张 claimant verdict）我无法核实条件存在」。
触发也不同：前者只要卡无 verdict 即报；后者**只在某 verdict 实际引用了该卡时**才报——
无引用则无 DANGLING。且 DANGLING 那条携带引用专属上下文，不是对「无 verdict」的重述。
作者「受众不同」的判断成立；即便合并，引用专属信息也会被丢掉。**保持现状。**

**Q2 —— 注入旧语义 vs `strict_independence` 参数，选哪个？**

**接受参数方案。** (1) 显式可读——docstring 写明了参数存在理由，后续维护者不用逆向；
(2) 注入方案（monkeypatch 或复刻旗标语义）更脆，正是「API 是不是我以为的那个」陷阱
（本轮作者测试 helper 跨类 AttributeError 的插曲就是坑 20 近亲）；(3) 代价「为测试而
API 化」已被作者诚实记录（缺口 1），默认值保持现行语义（满足 Constraint 2），生产
唯一调用点不受影响。卡片「二选一、以评审方可读性优先」的判定原则下，参数版可读性
占优。**无需第三条路。**

**Q3 —— 跨仓盲区（DSB 系 conditions 可能以 R2/P1 开头）？**

**推理方向大体对，需修正半句；且目前是经验真空，我未实测（客观测不了）。** 本轮
实测：`D:\15812\mo brain` 下 **`*.verdict.json` = 0 个**（递归 glob）——跨仓没有可
测数据。推理本身：`R2:`/`P1:` 这类规则/条款引用被吸进前缀集，只会让引用**更容易
命中**（「do not open with」类误报 WARN 减少——作者说的「误报减少」对）；但真悬挂
引用（引用了一个实际不存在的条件、其条件 id 恰好等于某规则编号）**会从漏报变为
沉默通过**——所以「漏报不变」这半句应修正为「漏报**可能增加**」。不过该漏报情形要
同时满足两个前提（某 verdict 的 unblocks 用规则编号当条件 id 引用 DSB 卡 + 该 DSB 卡
conditions 恰好以规则编号开头），概率极低，且今日 0 个跨仓 verdict 文件无从测试。
**判：保留已知盲区注记，待 DSB 系 verdict 文件实际存在时由后续跨仓卡实测；现在不
动正则**（把字母类改宽只会让「无前缀」的诚实信号更易被吞，现实现已是最保守选项）。
另记正则差异谱系（见 S1 段末）：实现多字母类与卡片 D1 规格、我 `-006` verdict JSON
一致，比我 `-006` 评审文档的单字母建议略强，本仓无害。

**Q4 —— DANGLING 与 DUPLICATE 要不要收敛成 `check_resolution_references`？**

**同意延后。** 现状两条规则已在 `check_verdict_pairs` 并列（L368-369），各
`out.extend` 一次，互不影响；lint `main()` 输出本就无排序承诺；收敛是纯重构，不解决
任何缺陷，却要动两条规则的测试位置。作者「超本卡范围、另立卡」的判断正确。
